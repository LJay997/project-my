实现说明：通用 Excel 导出脱敏机制

依据：.trae/documents/masking-demo-file-export-plan.md ｜ 模块：spring ｜ 更新：2026-10-25

一、设计决策

1. 统一判定入口 SensitiveValues

JSON 序列化、Excel 单元格写出、Bean 级反射改写三条链路统一调用 SensitiveValues.maskIfNeeded(Sensitive, String)，避免出现两套权限判断逻辑漂移。

public static String maskIfNeeded(Sensitive sensitive, String value) {
    if (sensitive == null || value == null) return value;
    if (UserContextHolder.hasPermission(sensitive.permission())) return value;
    return MaskRules.mask(sensitive.type(), value);
}

2. 选择单元格级 CellWriteHandler

使用 EasyExcel 4.0.3 的 afterCellDataConverted(CellWriteHandlerContext)，通过 context.getHeadData().getField() 读取字段上的 @Sensitive，再以 context.getFirstCellData().setStringValue(...) 改写单元格。

候选方案结论
Converter<String>会替换全局 String 转换器，影响面过大，放弃
Bean 级预改写（SensitiveDataMasker）需复制列表且会改源对象，降级为可选的通用工具
AOP 拦截 doWriteEasyExcel 为流式 Builder/静态调用，无法稳定拦截
CellWriteHandler采用：字段级、行级、零侵入、不改源 Bean

3. 表头与非字符串单元格默认跳过

context.getHead()==true 时不处理，保证列名不变；getStringValue()==null 时自然跳过，因此数字列（如年龄、用户ID）不会被误脱敏。

4. 手机号为确定性 mock 数据

不在 User 实体新增 phone 字段，避免触及约 47 处构造器调用与 /api/users 的明文输出风险；JSON 与导出共用 DemoMockData.phoneOf(userId)，保证两种输出同名值一致。

二、偏差

规范原文实际实现原因
4.6 使用 @InjectMocks 装配 MaskingExportServiceImpl 在 MaskingExportServiceTest 中用 new MaskingExportServiceImpl() + ReflectionTestUtils.setField 该实现类使用字段注入，@InjectMocks 同样可行；此处保留显式装配以与既有 ExcelServiceTest 风格一致，行为等价
4.11 仅要求“xlsx Content-Type”断言 测试改用 content().contentTypeCompatibleWith(...) prepareDownload 调用了 setCharacterEncoding(UTF-8)，实际响应头为 ...sheet;charset=UTF-8；改用兼容匹配，不削弱校验，也不移除对文本错误响应有益的编码设置
4.11 示例使用 Mockito willReturn 全部改为 thenReturn 项目内 Mockito 版本不支持 OngoingStubbing.willReturn

三、权衡

取舍点选择代价 / 收益
脱敏时机 单元格写出阶段 收益：不改源 DTO、任意模型自动生效；代价：依赖 Head#getField()，动态 List<List<String>> 表头场景不生效
既有导出迁移 ExcelServiceImpl 去掉 maskBeans，改用 MaskingExcelWriter.builder 收益：证明机制可复用、去掉对源 DTO 的原地改写；代价：需移除 SensitiveDataMasker 的注入与测试装配
处理器实例 静态单例复用 处理器无状态，可安全共享；registerWriteHandler 为 Workbook 级，多 Sheet 同时生效
注解复用 继续使用 @Sensitive，不新增注解 收益：JSON 与 Excel 元数据同源；代价：无 Excel 专属配置（如自定义掩码字符），当前需求无需

四、未决问题

  • 动态表头导出（List<List<String>>）没有字段元数据，无法走本机制，需要业务侧自行脱敏或后续增加“按列索引配置”的处理器。
  • 异步导出线程不会继承 UserContextHolder 的 ThreadLocal，如后续引入异步导出，需在任务入口显式设置权限上下文。
  • 当前仅覆盖 EasyExcel；CSV/PDF 等格式仍需复用 SensitiveDataMasker（Bean 级）或直接调用 SensitiveValues。
  • DemoMockData.phoneOf 仅为演示数据；接入真实手机号字段时需同步评估 /api/users 等既有接口的脱敏配置。
