### 🔒 MySQL InnoDB 锁机制速查表

#### 1. 锁粒度与类型概览

| 锁粒度 | 锁类型 | 核心特点 | 典型场景 |
| :--- | :--- | :--- | :--- |
| **行级锁** | 记录锁 (Record Lock) | 锁住索引上的一条记录 | `UPDATE ... WHERE id = 10` |
| | 间隙锁 (Gap Lock) | 锁住索引记录之间的空隙，防止插入 | RR级别下范围查询 |
| | 临键锁 (Next-Key Lock) | 记录锁 + 间隙锁，左开右闭区间 | RR级别下默认锁算法 |
| **表级锁** | 意向锁 (IS/IX) | 自动添加，用于快速判断表锁冲突 | 所有DML语句自动触发 |
| | 元数据锁 (MDL) | 保护表结构，防止DDL与DML并发 | 所有访问表的操作 |
| | 手动表锁 | 显式加锁，粒度粗，并发低 | `LOCK TABLES t1 WRITE` |
| **全局锁** | 全局读锁 | 锁定整个实例，所有库表只读 | 全库逻辑备份 (`FLUSH TABLES WITH READ LOCK`) |

#### 2. 锁兼容性矩阵

理解锁冲突是排查死锁和锁等待的基础。

| 当前持有锁 \ 请求锁 | 共享锁 (S) | 排他锁 (X) | 意向共享锁 (IS) | 意向排他锁 (IX) |
| :--- | :--- | :--- | :--- | :--- |
| **共享锁 (S)** | ✅ 兼容 | ❌ 冲突 | ✅ 兼容 | ❌ 冲突 |
| **排他锁 (X)** | ❌ 冲突 | ❌ 冲突 | ❌ 冲突 | ❌ 冲突 |
| **意向共享锁 (IS)** | ✅ 兼容 | ❌ 冲突 | ✅ 兼容 | ✅ 兼容 |
| **意向排他锁 (IX)** | ❌ 冲突 | ❌ 冲突 | ✅ 兼容 | ✅ 兼容 |

> **核心规则**：意向锁之间完全兼容，它们仅与表级 S/X 锁互斥，与行级锁无直接冲突。

#### 3. 加锁规则与索引命中

InnoDB 的行锁是**加在索引项上**的，而非物理数据行。这是理解所有锁行为的前提。

| 查询条件 | 索引命中情况 | 加锁行为 | 并发影响 |
| :--- | :--- | :--- | :--- |
| **等值查询** | 命中唯一索引 | 仅加**记录锁** | 并发度高，无间隙锁 |
| **等值查询** | 命中非唯一索引 | 加**临键锁**（记录+间隙） | 防止插入，可能阻塞范围查询 |
| **范围查询** | 命中索引 | 加**临键锁** | 锁住整个范围，并发度低 |
| **无索引/索引失效** | 全表扫描 | **退化为表锁** | ⚠️ 严重阻塞，高并发雪崩 |
| **RC 隔离级别** | 命中索引 | 仅加**记录锁**，无间隙锁 | 并发度最高，互联网首选 |

#### 4. 隔离级别与锁行为差异

| 隔离级别 | 锁行为 | 幻读防护 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **READ COMMITTED (RC)** | 仅记录锁，无间隙锁 | ❌ 允许幻读 | 高并发互联网业务，需配合Row格式Binlog |
| **REPEATABLE READ (RR)** | 临键锁（记录+间隙） | ✅ 大多数场景防止 | MySQL默认，强一致性场景 |
| **SERIALIZABLE** | 所有读加共享锁，写加排他锁 | ✅ 完全防止 | 极端一致性要求，并发极低 |

#### 5. 线上避坑指南

*   **⚠️ 索引失效 = 表锁**：`WHERE` 条件未命中索引时，InnoDB 会对全表所有记录加锁，瞬间导致服务雪崩。务必使用 `EXPLAIN` 确认索引命中。
*   **⚠️ MDL 锁导致改表雪崩**：`ALTER TABLE` 等 DDL 操作会加 MDL 写锁，与所有 DML 的 MDL 读锁互斥。长事务未提交时执行 DDL，会导致后续所有查询阻塞。**改表前务必检查长事务**。
*   **⚠️ RC 级别无间隙锁**：在 RC 级别下，`SELECT ... FOR UPDATE` 不会加间隙锁，其他事务仍可插入新记录。若业务逻辑依赖“范围锁定”，需显式使用 `LOCK IN SHARE MODE` 或调整隔离级别。
*   **⚠️ 死锁预防**：多表操作时，**约定相同的访问顺序**；避免大事务，及时提交/回滚；对易死锁场景可考虑升级为表锁。
*   **⚠️ 锁监控**：使用 `SHOW ENGINE INNODB STATUS` 查看最近死锁信息；通过 `information_schema.INNODB_TRX`、`INNODB_LOCKS`、`INNODB_LOCK_WAITS` 实时监控锁等待。

### 💡 速查表使用建议

1.  **排查锁等待**：先看 `SHOW ENGINE INNODB STATUS`，确认锁类型和等待关系。
2.  **分析锁范围**：用 `EXPLAIN` 检查 SQL 是否命中索引，未命中则直接退化为表锁。
3.  **评估并发影响**：RC 级别锁范围最小，RR 级别因间隙锁可能阻塞更多操作。
4.  **预防死锁**：代码层面约定访问顺序，数据库层面监控长事务和 MDL 锁。
