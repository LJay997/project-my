# Java / Spring 常用设计模式面试总结

> 按三大维度划分：创建型、结构型、行为型，并单独列出 Spring 框架中的经典应用。

---

## 一、创建型模式（关注对象创建）

### 1. 单例模式（Singleton）

**核心思想**：保证一个类只有一个实例，提供全局访问点。

**Java 经典实现（双重检查锁）**：

```java
public class Singleton {
    private static volatile Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {                    // 第一次检查，避免不必要的加锁
            synchronized (Singleton.class) {
                if (instance == null) {            // 第二次检查，防止重复创建
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

**Spring 中的体现**：Bean 默认就是单例，由 IOC 容器管理生命周期。

```java
@Component // 默认 singleton 作用域
public class UserService { }
```

### 2. 工厂方法模式（Factory Method）

**核心思想**：定义创建对象的接口，让子类决定实例化哪个类。

```java
// 产品接口
public interface Payment {
    void pay(double amount);
}

// 具体产品
public class AliPay implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("支付宝支付: " + amount);
    }
}

public class WeChatPay implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("微信支付: " + amount);
    }
}

// 工厂接口
public interface PaymentFactory {
    Payment createPayment();
}

// 具体工厂
public class AliPayFactory implements PaymentFactory {
    @Override
    public Payment createPayment() { return new AliPay(); }
}

public class WeChatPayFactory implements PaymentFactory {
    @Override
    public Payment createPayment() { return new WeChatPay(); }
}
```

**Spring 中的体现**：`BeanFactory` / `FactoryBean` 就是工厂模式的典型应用。

```java
@Component
public class MyBean implements FactoryBean<Connection> {
    @Override
    public Connection getObject() {
        return DriverManager.getConnection("jdbc:mysql://localhost/db");
    }
    @Override
    public Class<?> getObjectType() { return Connection.class; }
}
```

### 3. 抽象工厂模式（Abstract Factory）

**核心思想**：提供一个创建一系列相关对象的接口，无需指定具体类。

```java
// 产品族
public interface Button { void render(); }
public interface TextField { void render(); }

// Windows 风格
public class WinButton implements Button {
    @Override

    @Override
    public void render() { System.out.println("Windows 文本框"); }
}

// Mac 风格
public class MacButton implements Button {
    @Override
    public void render() { System.out.println("Mac 按钮"); }
}
public class MacTextField implements TextField {
    @Override
    public void render() { System.out.println("Mac 文本框"); }
}

// 抽象工厂
public interface UIFactory {
    Button createButton();
    TextField createTextField();
}

// 具体工厂
public class WinUIFactory implements UIFactory {
    public Button createButton() { return new WinButton(); }
    public TextField createTextField() { return new WinTextField(); }

public class MacUIFactory implements UIFactory {
    public Button createButton() { return new MacButton(); }
    public TextField createTextField() { return new MacTextField(); }
```

### 4. 建造者模式（Builder）

**核心思想**：将复杂对象的构建与表示分离，逐步组装。

```java
public class HttpRequest {
    private final String url;
    private final String method;
    private final Map<String, String> headers;
    private final String body;

    private HttpRequest(Builder builder) {
        this.url = builder.url;
        this.method = builder.method;
        this.headers = builder.headers;
        this.body = builder.body;
    }

    public static class Builder {
        private String url;
        private String method = "GET";
        private Map<String, String> headers = new HashMap<>();
        private String body;

        public Builder url(String url) { this.url = url; return this; }
        public Builder method(String method) { this.method = method; return this; }
        public Builder header(String key, String value) {
            this.headers.put(key, value); return this;
        }
        public Builder body(String body) { this.body = body; return this; }

        public HttpRequest build() { return new HttpRequest(this); }
    }
}

// 使用
HttpRequest request = new HttpRequest.Builder()
    .url("https://api.example.com")
    .method("POST")
    .header("Content-Type", "application/json")
    .body("{\"name\":\"test\"}")
    .build();
```

**Spring 中的体现**：`StringBuilder` / `UriComponentsBuilder` / `RestTemplateBuilder`。

```java
UriComponents uri = UriComponentsBuilder
    .fromHttpUrl("https://api.example.com")
    .path("/users")
    .queryParam("page", 1)
    .build();
```

### 5. 原型模式（Prototype）

**核心思想**：通过拷贝现有实例来创建新对象，避免重复初始化。

```java
public class PrototypeConfig implements Cloneable {
    private String name;
    private List<String> tags;

    @Override
    public PrototypeConfig clone() {
        try {
            return (PrototypeConfig) super.clone(); // 浅拷贝
        } catch (CloneNotSupportedException e) {
            throw new RuntimeException(e);
        }
    }
}
```

**Spring 中的体现**：`@Scope("prototype")` 每次获取 Bean 都返回新实例。

```java
@Component
@Scope("prototype")
public class PrototypeBean { }
```

## 二、结构型模式（关注对象组合）

### 6. 适配器模式（Adapter）

**核心思想**：将一个类的接口转换成客户端期望的另一个接口。

```java
// 目标接口（客户端期望）
public interface LogService {
    void log(String message);
}

// 被适配者（已有类，接口不兼容）
public class Log4jLogger {
    public void debug(String msg) { System.out.println("[DEBUG] " + msg); }
}

// 适配器
public class Log4jAdapter implements LogService {
    private final Log4jLogger logger;

    public Log4jAdapter(Log4jLogger logger) {
        this.logger = logger;
    }

    @Override
    public void log(String message) {
        logger.debug(message); // 转换调用
    }
}
```

**Spring 中的体现**：`HandlerAdapter` 适配不同类型的 Controller。

```java
// Spring MVC 核心适配器
public interface HandlerAdapter {
    boolean supports(Object handler);
    ModelAndView handle(HttpServletRequest req, HttpServletResponse resp, Object handler);
}

// 适配 @RequestMapping 方法
public class RequestMappingHandlerAdapter implements HandlerAdapter {
    @Override
    public boolean supports(Object handler) {
        return handler instanceof HandlerMethod;
    }
}
```

### 7. 装饰器模式（Decorator）

**核心思想**：动态地给对象添加额外职责，比子类继承更灵活。

```java
// 基础组件
public interface Coffee {
    double cost();
    String description();
}

public class SimpleCoffee implements Coffee {
    @Override
    public double cost() { return 10.0; }
    @Override
    public String description() { return "咖啡"; }
}

// 装饰器基类
public abstract class CoffeeDecorator implements Coffee {
    protected final Coffee coffee;
    public CoffeeDecorator(Coffee coffee) { this.coffee = coffee; }
}

// 具体装饰器
public class MilkDecorator extends CoffeeDecorator {
    public MilkDecorator(Coffee coffee) { super(coffee); }
    @Override
    public double cost() { return coffee.cost() + 3.0; }
    @Override
    public String description() { return coffee.description() + "+牛奶"; }
}

public class SugarDecorator extends CoffeeDecorator {
    public SugarDecorator(Coffee coffee) { super(coffee); }
    @Override
    public double cost() { return coffee.cost() + 1.0; }
    @Override
    public String description() { return coffee.description() + "+糖"; }
}

// 使用
Coffee coffee = new SugarDecorator(new MilkDecorator(new SimpleCoffee()));
System.out.println(coffee.description() + " = " + coffee.cost());
// 输出: 咖啡+牛奶+糖 = 14.0
```

**Java 中的体现**：`BufferedInputStream` 包装 `FileInputStream`。

**Spring 中的体现**：`BeanWrapper`、`TransactionAwareCacheDecorator`。

### 8. 代理模式（Proxy）

**核心思想**：为其他对象提供代理以控制对这个对象的访问。

**JDK 动态代理示例**：

```java
// 接口
public interface UserService {
    String getUser(Long id);
}

// 目标对象
public class UserServiceImpl implements UserService {
    @Override
    public String getUser(Long id) {
        return "User-" + id;
    }
}

// 动态代理处理器
public class LoggingHandler implements InvocationHandler {
    private final Object target;

    public LoggingHandler(Object target) { this.target = target; }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("[前] 调用: " + method.getName());
        Object result = method.invoke(target, args);
        System.out.println("[后] 返回: " + result);
        return result;
    }
}

// 使用
UserService proxy = (UserService) Proxy.newProxyInstance(
    UserService.class.getClassLoader(),
    new Class[]{UserService.class},
    new LoggingHandler(new UserServiceImpl())
);
proxy.getUser(1L);
// [前] 调用: getUser
// [后] 返回: User-1
```

**Spring 中的体现**：AOP 底层就是代理模式（JDK 动态代理 / CGLIB）。

```java
@Aspect
@Component
public class LogAspect {
    @Around("execution(* com.example.service.*.*(..))")
    public Object log(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = pjp.proceed();
        System.out.println(pjp.getSignature() + " 耗时: " + (System.currentTimeMillis() - start) + "ms");
        return result;
    }
}
```

### 9. 外观模式（Facade）

**核心思想**：为子系统中的一组接口提供统一入口，简化调用。

```java
// 子系统
public class CPU {
    public void start() { System.out.println("CPU 启动"); }
}
public class Memory {
    public void load() { System.out.println("内存加载"); }
}
public class Disk {
    public void read() { System.out.println("磁盘读取"); }
}

// 外观
public class ComputerFacade {
    private final CPU cpu = new CPU();
    private final Memory memory = new Memory();
    private final Disk disk = new Disk();

    public void start() {
        cpu.start();
        memory.load();
        disk.read();
        System.out.println("电脑启动完成");
    }
}

// 使用
new ComputerFacade().start();
```

**Spring 中的体现**：`JdbcTemplate` 封装了 `Connection`、`Statement`、`ResultSet` 的复杂操作。

### 10. 桥接模式（Bridge）

**核心思想**：将抽象部分与实现部分分离，使它们可以独立变化。

```java
// 实现维度
public interface MessageSender {
    void send(String message);
}

public class EmailSender implements MessageSender {
    @Override
    public void send(String message) { System.out.println("邮件: " + message); }
}

public class SmsSender implements MessageSender {
    @Override
    public void send(String message) { System.out.println("短信: " + message); }
}

// 抽象维度
public abstract class Notification {
    protected final MessageSender sender;

    public Notification(MessageSender sender) { this.sender = sender; }

    public abstract void notify(String user, String content);
}

public class UrgentNotification extends Notification {
    public UrgentNotification(MessageSender sender) { super(sender); }

    @Override
    public void notify(String user, String content) {
        sender.send("[加急] " + user + ": " + content);
    }
}

// 使用：两个维度独立变化
Notification n = new UrgentNotification(new SmsSender());
n.notify("张三", "服务器宕机！");
```

### 11. 组合模式（Composite）

**核心思想**：将对象组合成树形结构，统一处理个别对象和组合对象。

```java
public abstract class MenuComponent {
    public void add(MenuComponent c) { throw new UnsupportedOperationException(); }
    public void print() { throw new UnsupportedOperationException(); }
}

public class MenuItem extends MenuComponent {
    private final String name;
    public MenuItem(String name) { this.name = name; }
    @Override
    public void print() { System.out.println("  - " + name); }
}

public class Menu extends MenuComponent {
    private final String name;
    private final List<MenuComponent> children = new ArrayList<>();

    public Menu(String name) { this.name = name; }
    @Override
    public void add(MenuComponent c) { children.add(c); }
    @Override
    public void print() {
        System.out.println(name);
        children.forEach(MenuComponent::print);
    }
}

// 使用
Menu root = new Menu("系统菜单");
root.add(new MenuItem("用户管理"));
Menu sub = new Menu("权限管理");
sub.add(new MenuItem("角色管理"));
sub.add(new MenuItem("资源管理"));
root.add(sub);
root.print();
```

### 12. 享元模式（Flyweight）

**核心思想**：共享细粒度对象，减少内存占用。

```java
public class ConnectionPool {
    private final List<Connection> pool = new ArrayList<>();
    private final int maxSize;

    public ConnectionPool(int maxSize) {
        this.maxSize = maxSize;
        for (int i = 0; i < maxSize; i++) {
            pool.add(createConnection());
        }
    }

    public synchronized Connection getConnection() {
        if (pool.isEmpty()) {
            try { wait(); } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
        }
        return pool.remove(0);
    }

    public synchronized void returnConnection(Connection conn) {
        pool.add(conn);
        notifyAll();
    }

    private Connection createConnection() {
        return DriverManager.getConnection("jdbc:mysql://localhost/db");
    }
}
```

**Spring 中的体现**：`@Cacheable` 缓存复用结果，数据库连接池（HikariCP）。

## 三、行为型模式（关注对象交互）

### 13. 策略模式（Strategy）

**核心思想**：定义一系列算法，封装起来并可互相替换。

```java
// 策略接口
@FunctionalInterface
public interface DiscountStrategy {
    double apply(double price);
}

// 具体策略
public class FullReductionDiscount implements DiscountStrategy {
    @Override
    public double apply(double price) {
        return price >= 100 ? price - 20 : price;
    }
}

public class PercentageDiscount implements DiscountStrategy {
    @Override
    public double apply(double price) {
        return price * 0.9; // 九折
    }
}

// 上下文
public class Order {
    private DiscountStrategy strategy;
    public void setStrategy(DiscountStrategy strategy) { this.strategy = strategy; }
    public double calculatePrice(double price) { return strategy.apply(price); }
}
```

**Spring 中的体现**：通过依赖注入 + `@Qualifier` 动态选择策略 Bean。

```java
@Service
public class OrderService {
    private final Map<String, DiscountStrategy> strategies;

    // Spring 自动注入所有 DiscountStrategy 实现，key = Bean 名称
    public OrderService(Map<String, DiscountStrategy> strategies) {
        this.strategies = strategies;
    }

    public double calculate(String type, double price) {
        return strategies.getOrDefault(type, p -> p).apply(price);
    }
}
```

### 14. 模板方法模式（Template Method）

**核心思想**：定义算法骨架，将步骤延迟到子类实现。

```java
public abstract class AbstractOrderProcessor {

    // 模板方法：固定流程
    public final void process(Order order) {
        validate(order);
        calculatePrice(order);
        deductStock(order);
        afterProcess(order); // 钩子方法
    }

    protected abstract void validate(Order order);
    protected abstract void calculatePrice(Order order);

    // 通用实现
    protected void deductStock(Order order) {
        System.out.println("扣减库存");
    }

    // 钩子，子类可选覆盖
    protected void afterProcess(Order order) { }
}

public class NormalOrderProcessor extends AbstractOrderProcessor {
    @Override
    protected void validate(Order order) { System.out.println("普通订单校验"); }

    @Override
    protected void calculatePrice(Order order) { order.setPrice(order.getPrice()); }
}
```

**Spring 中的体现**：`JdbcTemplate`、`RestTemplate`、`TransactionTemplate`。

```java
// JdbcTemplate 就是模板方法：固定流程（获取连接→执行SQL→处理结果→关闭连接）
 jdbcTemplate.query("SELECT * FROM user WHERE id = ?",
     new Object[]{1},
     (rs, rowNum) -> new User(rs.getLong("id"), rs.getString("name"))
 );
```

### 15. 观察者模式（Observer）

**核心思想**：定义对象间一对多依赖，当对象状态变化时通知所有依赖者。

```java
// 事件
public class OrderEvent {
    private final String orderId;
    private final long timestamp;

    public OrderEvent(String orderId) {
        this.orderId = orderId;
        this.timestamp = System.currentTimeMillis();
    }
}

// 发布者
public class OrderService extends Observable {
    public void placeOrder(String orderId) {
        setChanged();
        notifyObservers(new OrderEvent(orderId));
    }
}

// 观察者
public class InventoryObserver implements Observer {
    @Override
    public void update(Observable o, Object arg) {
        OrderEvent event = (OrderEvent) arg;
        System.out.println("库存系统收到订单: " + event.getOrderId());
    }
}
```

**Spring 中的体现**：`ApplicationEvent` + `ApplicationListener` / `@EventListener`。

```java
// 事件
public class OrderCreatedEvent extends ApplicationEvent {
    private final String orderId;
    public OrderCreatedEvent(Object source, String orderId) {
        super(source);
        this.orderId = orderId;
    }
    public String getOrderId() { return orderId; }
}

// 发布
@Autowired
private ApplicationEventPublisher publisher;

public void createOrder(String orderId) {
    publisher.publishEvent(new OrderCreatedEvent(this, orderId));
}

// 监听
@Component
public class OrderEventListener {
    @EventListener
    public void onOrderCreated(OrderCreatedEvent event) {
        System.out.println("收到订单事件: " + event.getOrderId());
    }
}
```

### 16. 责任链模式（Chain of Responsibility）

**核心思想**：将请求沿着处理者链传递，每个处理者决定处理或转发。

```java
public abstract class Handler {
    protected Handler next;

    public Handler setNext(Handler next) {
        this.next = next;
        return next;
    }

    public abstract void handle(Request request);
}

public class AuthHandler extends Handler {
    @Override
    public void handle(Request request) {
        if (!request.hasToken()) {
            System.out.println("认证失败");
            return;
        }
        System.out.println("认证通过");
        if (next != null) next.handle(request);
    }
}

public class RateLimitHandler extends Handler {
    @Override
    public void handle(Request request) {
        if (isRateLimited(request)) {
            System.out.println("限流拦截");
            return;
        }
        System.out.println("限流通过");
        if (next != null) next.handle(request);
    }
}

public class LogHandler extends Handler {
    @Override
    public void handle(Request request) {
        System.out.println("记录日志: " + request.getPath());
        if (next != null) next.handle(request);
    }
}

// 组装
Handler chain = new AuthHandler();
chain.setNext(new RateLimitHandler()).setNext(new LogHandler());
chain.handle(request);
```

**Spring 中的体现**：Spring Security Filter Chain、Spring Interceptor 链。

```java
// Spring Security 责任链
http.csrf().disable()
    .authorizeHttpRequests(auth -> auth
        .requestMatchers("/public/**").permitAll()
        .anyRequest().authenticated()
    )
    // 本质就是一个过滤器链：SecurityFilterChain
    .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);
```

```java
// Spring MVC Interceptor 链
@Component
public class LogInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest req, HttpServletResponse resp, Object handler) {
        System.out.println("[Interceptor] 请求: " + req.getRequestURI());
        return true; // true=继续链, false=中断
    }
}
```

### 17. 命令模式（Command）

**核心思想**：将请求封装为对象，支持参数化、排队、撤销。

```java
public interface Command {
    void execute();
    void undo(); // 可选：撤销
}

public class LightOnCommand implements Command {
    private final Light light;

    public LightOnCommand(Light light) { this.light = light; }

    @Override
    public void execute() { light.on(); }

    @Override
    public void undo() { light.off(); }
}

// 调用者
public class RemoteControl {
    private final Stack<Command> history = new Stack<>();

    public void execute(Command cmd) {
        cmd.execute();
        history.push(cmd);
    }

    public void undo() {
        if (!history.isEmpty()) {
            history.pop().undo();
        }
    }
}
```

### 18. 状态模式（State）

**核心思想**：对象在内部状态改变时改变行为。

```java
// 状态接口
public interface OrderState {
    void next(OrderContext context);
    void printStatus();
}

// 具体状态
public class NewOrder implements OrderState {
    @Override
    public void next(OrderContext context) {
        context.setState(new PaidOrder());
    }
    @Override
    public void printStatus() { System.out.println("新建订单"); }
}

public class PaidOrder implements OrderState {
    @Override
    public void next(OrderContext context) {
        context.setState(new ShippedOrder());
    }
    @Override
    public void printStatus() { System.out.println("已支付"); }
}

public class ShippedOrder implements OrderState {
    @Override
    public void next(OrderContext context) {
        context.setState(new CompletedOrder());
    }
    @Override
    public void printStatus() { System.out.println("已发货"); }
}

public class CompletedOrder implements OrderState {
    @Override
    public void next(OrderContext context) {
        System.out.println("订单已完成");
    }
    @Override
    public void printStatus() { System.out.println("已完成"); }
}

// 上下文
public class OrderContext {
    private OrderState state;

    public OrderContext() { this.state = new NewOrder(); }
    public void setState(OrderState state) { this.state = state; }
    public void next() { state.next(this); }
    public void printStatus() { state.printStatus(); }
}
```

### 19. 迭代器模式（Iterator）

**核心思想**：提供一种方法顺序访问集合中的元素，不暴露内部结构。

```java
public interface Iterator<T> {
    boolean hasNext();
    T next();
}

public class ListIterator<T> implements Iterator<T> {
    private final List<T> list;
    private int index = 0;

    public ListIterator(List<T> list) { this.list = list; }

    @Override
    public boolean hasNext() { return index < list.size(); }

    @Override
    public T next() { return list.get(index++); }
}
```

**Java 中的体现**：`java.util.Iterator`、增强 for 循环。

```java
List<String> list = List.of("A", "B", "C");
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    System.out.println(it.next());
}
```

### 20. 中介者模式（Mediator）

**核心思想**：用一个中介对象来封装一系列对象之间的交互，解耦对象间的直接引用。

```java
// 中介者
public class ChatMediator {
    private final List<User> users = new ArrayList<>();

    public void register(User user) { users.add(user); }

    public void sendMessage(String msg, User sender) {
        users.stream()
            .filter(u -> !u.equals(sender))
            .forEach(u -> u.receive(msg));
    }
}

// 同事对象
public class User {
    private final String name;
    private final ChatMediator mediator;

    public User(String name, ChatMediator mediator) {
        this.name = name;
        this.mediator = mediator;
        mediator.register(this);
    }

    public void send(String msg) {
        System.out.println(name + " 发送: " + msg);
        mediator.sendMessage(msg, this);
    }

    public void receive(String msg) {
        System.out.println(name + " 收到: " + msg);
    }
}
```

**Spring 中的体现**：`DispatcherServlet` 充当中介者，协调各组件交互。

### 21. 备忘录模式（Memento）

**核心思想**：在不破坏封装性的前提下，保存对象内部状态以便恢复。

```java
public class EditorMemento {
    private final String content;

    public EditorMemento(String content) { this.content = content; }
    public String getContent() { return content; }
}

public class Editor {
    private String content;

    public void setContent(String content) { this.content = content; }
    public String getContent() { return content; }

    public EditorMemento save() { return new EditorMemento(content); }
    public void restore(EditorMemento m) { this.content = m.getContent(); }
}

// 使用
Editor editor = new Editor();
editor.setContent("版本1");
EditorMemento m1 = editor.save();
editor.setContent("版本2");
editor.restore(m1); // 恢复到版本1
```

### 22. 访问者模式（Visitor）

**核心思想**：在不修改对象结构的前提下，定义新操作。

```java
public interface Element {
    void accept(Visitor visitor);
}

public interface Visitor {
    void visit(Circle circle);
    void visit(Rectangle rectangle);
}

public class Circle implements Element {
    private final double radius;

    public Circle(double r) { this.radius = r; }
    public double getRadius() { return radius; }

    @Override
    public void accept(Visitor v) { v.visit(this); }
}

public class Rectangle implements Element {
    private final double width, height;

    public Rectangle(double w, double h) { this.width = w; this.height = h; }
    public double getWidth() { return width; }
    public double getHeight() { return height; }

    @Override
    public void accept(Visitor v) { v.visit(this); }
}

// 具体访问者：面积计算
public class AreaCalculator implements Visitor {
    @Override
    public void visit(Circle c) {
        System.out.println("圆面积: " + Math.PI * c.getRadius() * c.getRadius());
    }

    @Override
    public void visit(Rectangle r) {
        System.out.println("矩形面积: " + r.getWidth() * r.getHeight());
    }
}

// 使用
List<Element> shapes = List.of(new Circle(5), new Rectangle(3, 4));
Visitor calculator = new AreaCalculator();
shapes.forEach(s -> s.accept(calculator));
```

## 五、面试高频问答

### Q1: Spring AOP 用的是哪种代理模式？JDK 和 CGLIB 有什么区别？

| | JDK 动态代理 | CGLIB 代理 |
|---|---|---|
| **原理** | 基于接口，`Proxy.newProxyInstance` | 基于继承，生成子类字节码 |
| **要求** | 目标类必须实现接口 | 目标类不能是 `final` |
| **性能** | 创建快，调用稍慢 | 创建慢，调用快 |
| **Spring 默认** | 有接口时用 JDK | 无接口时回退 CGLIB |
| **强制 CGLIB** | `spring.aop.proxy-target-class=true` | -- |

### Q2: Spring 事件机制如何体现观察者模式？

```java
// 发布者（被观察者）
publisher.publishEvent(new OrderCreatedEvent(this, orderId));

// 监听器（观察者）-- 同步执行
@EventListener
public void handle(OrderCreatedEvent event) { ... }

// 改为异步
@EventListener
@Async
public void handleAsync(OrderCreatedEvent event) { ... }
```

事件、发布者、监听器三者松耦合，完全符合观察者模式。

### Q3: JdbcTemplate 如何体现模板方法模式？

```
execute(ConnectionCallback)     <- 模板方法（固定骨架）
  |- 获取 Connection（Spring 管理）
  |- 调用 doInConnection（用户实现）
  |- 异常翻译（DataAccessException）
  +- 关闭 Connection（Spring 管理）
```

用户只需实现 `ConnectionCallback` / `RowMapper` 等回调接口，不关心资源释放。

### Q4: 责任链模式在 Spring Security 中如何体现？

```
HTTP请求 -> FilterChainProxy -> SecurityFilterChain
  |- SecurityContextPersistenceFilter   (恢复安全上下文)
  |- UsernamePasswordAuthenticationFilter (认证)
  |- AuthorizationFilter               (授权)
  |- ExceptionTranslationFilter         (异常处理)
  +- FilterSecurityInterceptor          (最终拦截)
```

每个 Filter 决定放行或拒绝，形成责任链。
